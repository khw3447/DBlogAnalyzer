DBLogAnalyzer.exe 만드는 방법 (Windows PC에서 1회만)

0) 준비물
   - Windows PC (배포 대상 PC와 달라도 됩니다. 여기서 exe만 만들어서 옮기면 됩니다)
   - Python 3.11 / 3.12 / 3.13 중 하나, 반드시 **64비트(64-bit)** 버전:
     https://www.python.org/downloads/ 에서 "Windows installer (64-bit)"를 받으세요.
     ("32-bit"라고 적힌 걸 받으면 안 됩니다 - 동봉된 wheels가 64비트 전용이라 설치가 실패합니다.
     실행 파일 이름은 똑같이 생겼으니 다운로드 페이지에서 (64-bit) 글자를 꼭 확인하세요.)
     설치 화면에서 아래 2개 꼭 체크하세요.
       [v] Add python.exe to PATH
       [v] tcl/tk and IDLE (기본값이라 보통 이미 체크되어 있습니다)
   - (wheels 폴더가 동봉되어 있다면) 인터넷 없이도 빌드 가능합니다.
     wheels 폴더가 없는 배포본이라면 이 PC에 인터넷이 필요합니다.
   - build_windows.bat이 이제 Python이 64비트인지 자동으로 확인하고, 32비트면 바로 알려줍니다.

1) 이 폴더(DBLogAnalyzer-python) 전체를 그 PC로 복사합니다.

2) 폴더 안에서 build_windows.bat 파일을 더블클릭합니다.
   - wheels 폴더가 있으면 그걸 이용해 완전히 오프라인으로 패키지를 설치합니다(인터넷 접속 시도 안 함).
   - 없으면 인터넷(pip, pypi.org)으로 설치를 시도합니다.
   - 패키지 설치와 exe 빌드 과정이 검은 창(cmd)에 실시간으로 죽 표시됩니다. 특히 exe 빌드
     단계(3/3)는 원래 수십 초~몇 분 정도 걸릴 수 있습니다 - 화면에 새 줄이 잠시 안 늘어나도
     멈춘 게 아니니 창을 닫거나 Ctrl+C로 중단하지 말고 끝까지 기다려 주세요.
   - 다 끝나면 build_log.txt 요약이 표시된 뒤 "계속하려면 아무 키나 누르십시오..."가 뜹니다.
     이때 아무 키나 눌러야 창이 닫힙니다(자동으로 안 닫힙니다).

   만약 더블클릭했는데 창이 잠깐 떴다가 바로 사라지거나 "아무 반응이 없다"면: bat 파일을
   더블클릭하지 말고, 아래처럼 명령 프롬프트를 먼저 열어서 실행해 보세요. 이러면 오류가 나도
   창이 저절로 닫히지 않아서 내용을 볼 수 있습니다.
     1. 이 폴더를 파일 탐색기에서 열고, 주소창에 "cmd"라고 입력한 뒤 Enter
        (또는 시작 메뉴 > cmd 검색 > 명령 프롬프트 실행 후 "cd 이-폴더-경로")
     2. build_windows.bat 라고 입력 후 Enter

   (수동으로 직접 하고 싶다면, 명령 프롬프트에서 아래 두 줄을 순서대로 입력해도 됩니다)
   > python -m pip install --no-index --find-links wheels -r requirements.txt pyinstaller
   > python -m PyInstaller --onefile --windowed --name DBLogAnalyzer app.py

3) 빌드가 끝나면 dist 폴더 안에 DBLogAnalyzer.exe 가 생깁니다.
   이 파일 "하나만" 복사해서 폐쇄망 PC로 옮기면 됩니다. Python도, 다른 폴더/파일도 필요 없습니다.

4) 문제가 생기면, 화면 캡처보다 **build_windows.bat과 같은 폴더에 생긴 build_log.txt 파일을
   그대로 보내주시는 게 훨씬 정확합니다.** (실행할 때마다 새로 덮어씁니다.) exe 자체를 실행했을 때
   문제가 생긴 경우라면 그때는 어떤 메시지가 떴는지 화면을 캡처해서 알려주세요.

자주 겪는 문제

Q. build_windows.bat 실행 화면의 한글이 깨져 보입니다.
A. bat 파일 자체는 UTF-8로 되어 있는데 한국어 Windows의 cmd 창은 보통 CP949 코드페이지를 쓰기
   때문에 생기는 문제였습니다. 이번 판에서는 bat 파일 시작 부분에 코드페이지를 맞추도록 고쳤습니다.
   여전히 깨진다면 build_log.txt를 보내주세요(이 파일은 영문으로만 기록해서 깨질 일이 없습니다).

Q. "WinError 10061" (연결을 거부했으므로...) 오류가 뜹니다.
A. 이건 거의 항상 pip가 인터넷(pypi.org)에 접속하려다 막혀서 나는 오류입니다(회사 프록시/방화벽).
   동봉된 wheels 폴더를 이용하면 인터넷 접속 자체를 시도하지 않으므로 이 문제를 피할 수 있습니다.
   그래도 이 오류가 뜬다면, wheels 폴더 인식에 실패했을 수 있습니다 - build_log.txt 맨 위쪽에
   "found wheels folder" 인지 "wheels folder not found"인지가 찍히니, 그 파일을 보내주시면
   바로 원인을 알 수 있습니다.

Q. wheels 폴더로 설치했는데도 실패합니다.
A. 두 가지를 확인하세요.
   1) build_windows.bat이 뜨자마자 "Python 아키텍처: 32bit"라고 나온다면 - 32비트 Python이
      설치된 것입니다. 동봉된 wheels는 64비트(win_amd64) 전용이라 설치가 안 됩니다.
      python.org에서 "Windows installer (64-bit)"로 재설치하세요.
   2) "python --version"으로 버전을 확인하세요. 동봉된 wheels는 3.11 / 3.12 / 3.13용입니다.
      다른 버전이면 인터넷이 되는 PC에서 아래 명령으로 해당 버전용 wheels를 새로 받아
      wheels 폴더에 넣으세요 (버전 숫자만 바꾸면 됩니다).
      > python -m pip download --only-binary=:all: --platform win_amd64 ^
          --python-version 3.13 --implementation cp -d wheels -r requirements.txt pyinstaller

Q. 실행 환경이 64비트인데 프로그램도 64비트로 만들어지는 게 맞나요?
A. 네. Python/PyInstaller로 만드는 exe는 빌드에 쓴 Python이 64비트면 결과물도 64비트입니다
   (위 아키텍처 확인 단계에서 자동으로 체크합니다). 참고로 이 저장소의 Java 버전(최상위 폴더)에서
   만드는 exe는 다른 방식이라 이야기가 다릅니다 - Launch4j라는 도구로 만드는데, 이 도구는 "런처"
   부분을 항상 32비트로만 만듭니다(도구 자체의 한계). 다만 이 런처는 JVM을 직접 담는 게 아니라
   64비트 javaw.exe를 자식 프로세스로 실행만 해주는 얇은 껍데기라서, 64비트 JRE만 제대로
   연결되면 실제 동작에는 문제가 없습니다. 지금 쓰고 계신 Python 버전에는 해당하지 않는 내용입니다.

Q. 프로그램 화면이나 불러온 로그 파일의 한글이 깨져 보입니다.
A. 최신 코드에서 한글 파일 인코딩(UTF-8/EUC-KR/CP949) 자동 감지 로직을 더 정확하게 고쳤습니다.
   여전히 깨진다면: (1) 프로그램 자체의 버튼/라벨 글자가 깨지는지, (2) 붙여넣거나 불러온 로그 "내용"
   글자가 깨지는지 구분해서 알려주세요. 원인이 서로 다릅니다.
